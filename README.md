# Savvy

Savvy is a meeting assistant for macOS and Windows 11 x64. It prepares a brief from your own source documents, then offers source-grounded guidance during a live conversation. Preparation can be scoped to a specific client or kept general.

## Where your data goes

Savvy keeps your documents and history on your computer, but live transcription is not local. Read this before pointing it at anything confidential.

| Data                       | Stays on your computer                      | Sent to a third party                             |
| -------------------------- | ------------------------------------------- | ------------------------------------------------- |
| Source documents           | Referenced read-only, never copied          | Selected excerpts only, at recommendation time    |
| Derived chunks and indexes | Private local SQLite                        | Selected excerpts only                            |
| **Meeting audio**          | Retention-controlled local files            | **Yes — streamed to your transcription provider** |
| Transcript                 | Retention-controlled local files            | Recent relevant turns, at recommendation time     |
| Meeting brief              | Private and versioned                       | The whole brief document, at recommendation time  |
| Provider credentials       | macOS Keychain / Windows Credential Manager | Authorization header only                         |

**Transcription** requires a Deepgram or AssemblyAI account. Meeting audio is streamed to that provider as it is captured — there is no offline transcription mode in the current build. Savvy sets Deepgram's `mip_opt_out=true` so your audio is not used to train their models; check AssemblyAI's terms for their equivalent.

**Recommendations** are generated by a CLI you already have installed — either OpenAI's Codex CLI or Anthropic's Claude Code. Savvy shells out to it, so excerpts and recent transcript turns reach whichever provider that CLI is signed in to, under your own account and its terms.

On macOS, application-owned directories use owner-only permissions (`0700`) and sensitive files `0600`. On Windows, Savvy stores its data under the signed-in user’s AppData directory and inherits that profile’s access permissions. Disk encryption depends on your operating system configuration; Savvy does not encrypt recordings or transcripts itself. Audio and transcripts are deleted after 30 days, with cleanup running at startup. Removing a client deletes derived data but never touches your source folder.

## When Savvy speaks up

During a meeting the overlay mascot switches to _thinking_ for exactly three reasons. The status line first says **Checking notes** while the model reads your brief, notes, and transcript, then names the reason once it starts composing:

1. **Answering their question** — the other side asked a question.
2. **Checking a red line** — someone touched a hard constraint from your brief.
3. **Getting advice** — you pressed Advice.

Between those, Savvy periodically re-reads your brief and notes against the last minute of conversation — **Checking notes**, then **Thinking** — with Advice still available; if it finds something concrete a card labelled _Savvy noticed_ appears. Savvy never thinks when no recommendation CLI is signed in; it shows one notice instead. Quitting Savvy during a meeting stops the meeting first.

## Install

Download `Savvy_<version>_aarch64.dmg` from the [latest release](https://github.com/jamalavedra/savvy/releases/latest), open it, and drag Savvy to Applications.

macOS requires version 13 or newer. Apple Silicon builds are released; Intel is buildable but unsupported.

Windows targets Windows 11 on Intel/AMD x64 PCs. Until a Windows release is published, download `savvy-windows-x64-preview` from a successful Verify workflow and run the included `Savvy_*_x64-setup.exe`. The installer runs for the current user and downloads WebView2 if needed. Preview installers do not have Authenticode signatures. Release updater artifacts use Savvy's existing updater signing key. Windows 10, ARM64, and WSL provider integration are not supported targets.

## Building from source

Prerequisites:

- macOS: macOS 13+ on Apple Silicon and Xcode Command Line Tools.
- Windows: Windows 11 x64, Visual Studio Build Tools with the **Desktop development with C++** workload and Windows SDK, and WebView2 Runtime.
- Node 22 and pnpm 10 (see `volta` in `package.json` for exact versions)
- Rust via `rustup` — `rust-toolchain.toml` pins the exact channel and installs it automatically

```bash
pnpm install --frozen-lockfile
pnpm verify        # format, typecheck, lint, tests, build, clippy
pnpm tauri dev
```

On macOS, first launch asks for microphone and screen-recording permission, then for a Deepgram or AssemblyAI API key. Windows goes directly to the API key step and checks microphone access when recording starts. Only the microphone is required to get past setup — but without system audio Savvy hears only you, and without a key nothing is transcribed at all.

To use recommendations you also need `codex` or `claude` installed and signed in; Savvy reports provider status in Settings. Windows supports native executables on `PATH` or in `%USERPROFILE%\.local\bin`, plus standard npm installations on `PATH` or in `%APPDATA%\npm`. npm installations also require `node.exe` on `PATH`. Reopen Savvy after installing a CLI or changing `PATH`. WSL installations are not used.

On Windows, enable microphone access for desktop apps under **Settings > Privacy & security > Microphone**. In Savvy's **General > System Audio Output**, select the playback device your meeting app uses. The default is the Windows default playback device, which may differ from a meeting app's selected headphones. Loopback captures all audio playing through that device, including other apps and Savvy's optional feedback cues. It does not capture the screen. Change the output selection between meetings. A device failure produces an error; reconnect it and restart the meeting. If system audio cannot start, the microphone keeps working and Savvy displays a warning.

Windows uses `Ctrl+Shift+M` by default. Closing the main window keeps Savvy in the system tray. If **Show Tray Icon** is disabled, closing the window quits Savvy after stopping the meeting; **Start Hidden** only applies when the tray icon is enabled.

Completed setup survives application updates. Microphone access is checked when you start a meeting. If macOS already lists Savvy as allowed but setup disagrees, use **Check again** to verify system-audio access through ScreenCaptureKit. If it still waits after you press Allow, choose **Reopen Savvy**. Savvy does not require Accessibility permission. Development-signed and release-signed builds can have different macOS permission identities.

If your preferred microphone is disconnected before a meeting starts, Savvy uses the system default for that recording and remembers your preference for when it reconnects. A disconnect during a meeting shows a capture error; stop the meeting, reconnect the device, and start again. Savvy does not switch formats inside an existing recording.

Using a Bluetooth headset's microphone can reduce the headset's playback quality while it records. Select your computer's built-in microphone or a USB microphone if you want to keep Bluetooth playback quality.

CI runs the full test suite on macOS and Windows, builds an unsigned Windows preview installer, and runs `cargo check` on Linux. Linux's native meeting integrations remain disabled. Automated checks do not verify audio devices or desktop behavior.

## Windows release acceptance

Before publishing the first Windows release, verify the following on a Windows 11 x64 PC using the installer artifact. These hardware checks remain outstanding until recorded against a specific build.

- [ ] Install as a standard user, including on a machine without WebView2. Launch from the Start menu.
- [ ] Save, replace, and delete a synthetic provider key. Relaunch to confirm persistence. Confirm no key appears in settings or logs.
- [ ] With authenticated Windows provider CLIs, generate a brief and receive a live recommendation. Check paths containing spaces and confirm no console window flashes.
- [ ] Transcribe both sides of a call using headphones. Try the default and an explicit playback device, silence followed by speech, and pause/resume. Confirm local recording and transcript history survive stopping and relaunching.
- [ ] Deny microphone access, disconnect input/output devices, and select an unavailable output. Confirm actionable errors, continued microphone recording when system capture fails, and recovery after restarting the meeting.
- [ ] Show, drag, expand, and collapse the overlay across monitors with different scaling. Confirm it stays clear of the taskbar, does not steal focus when shown, and its controls work with mouse and keyboard.
- [ ] Exercise shortcut capture/reset/conflicts, tray visibility, close-to-tray, hidden startup, login startup, and quitting during a meeting. Confirm provider processes and audio capture stop.
- [ ] Install an older signed-updater test build and update to a newer one through a controlled update manifest. Confirm settings, credentials, and history survive. Verify the release manifest contains both macOS and Windows entries before publishing.

## Repository layout

- `src/` — React interface.
- `src-tauri/` — desktop shell and Tauri commands.
- `crates/domain/` — stable application contracts.
- `crates/dossier/` — read-only scanning, extraction, and chunking of source documents.
- `crates/audio/` — microphone and system-audio capture, device enumeration, and WAV writing.
- `crates/transcription/` — hosted streaming transcription and cross-stream reconciliation.
- `crates/meeting/` — outline tracking, rolling context, and recommendation scheduling.
- `crates/recommendations/` — triggers and output validation.
- `crates/providers/` — the recommendation request contract and prompt rules.
- `crates/storage/` — private local persistence.
