# Security policy

Savvy handles meeting audio, transcripts, and private business documents. Bugs that expose that
material matter more here than the size of the code would suggest, and we would rather hear about
them early.

## Reporting a vulnerability

Report privately through [GitHub Security Advisories](https://github.com/jamalavedra/savvy/security/advisories/new).
Please don't open a public issue for a security bug.

Include what you did, what happened, and what you expected. A rough proof of concept helps more
than a polished one. You should get an acknowledgement within a week.

## What we consider in scope

- Client documents, transcripts, or audio reaching a network destination the user did not select
- Provider API keys leaking out of the macOS Keychain, into logs, or into crash output
- Local state readable by another user account on the same Mac
- Anything defeating the update signature check, or allowing an unsigned update to install
- Prompt injection in a source document that causes Savvy to exfiltrate other clients' data

## Known design limits

These are documented behaviour rather than vulnerabilities, though reports that they work
differently than described are very much in scope:

- **Meeting audio is streamed to a third-party transcription provider.** This is inherent to the
  current build — there is no working offline transcription. The README's "Where your data goes"
  table is the authoritative summary.
- Recommendations are generated by shelling out to a locally installed `codex` or `claude` CLI,
  so excerpts leave the machine under your own account with that vendor.
- Savvy relies on FileVault for encryption at rest and adds no application-layer encryption.

## Supported versions

Only the latest release receives fixes.
